# pilot_session_hardening (d1 Structural Summary)

- **Context Entry**: `context.md` describes the overall pilot Connect session hardening topic, emphasizing how the `YONA_BASE_PATH` normalization underpins RPC routing, anonymous session bootstrap exposure, CSRF issuance/validation, and the frontend session bootstrapping flow. Points readers to `authentication/better_auth_integration` for related auth patterns.

- **Detailed Manifest**: `pilot_session_hardening.md`
  - **Task & Reach**: Documents mounting Connect handlers under `YONA_BASE_PATH/rpc`, hosting the anonymous session bootstrap at `YONA_BASE_PATH/api/auth/session`, and enforcing CSRF protections end-to-end (handlers, tokens, and bootstrap flow).
  - **Key Changes**:
    - Router handlers now mount beneath the normalized base path plus `/rpc`.
    - Anonymous session bootstrap issues `yona_session`, `yona_csrf_token`, and `X-CSRF-Token`, supporting frontend reads before Connect calls.
    - Frontend pilot mutations read the bootstrap to keep CSRF tokens synchronized before invoking RPC.
  - **File Footprint**: `internal/httpapi/connect/pilot.go`, `internal/auth/session.go`, `apps/app/src/lib/pilot-session.ts`.
  - **Flow**: Runtime config → fetch `BasePath/api/auth/session` → server ensures session/CSRF headers/cookies → client persists tokens → subsequent RPC calls hit `BasePath/rpc` carrying `X-CSRF-Token`.
  - **Architecture & Dependencies**: 
    - `normalizeBasePath` ensures consistent slashes before `joinBasePath(basePath, "/api/auth/session")` and `"/rpc"`.
    - Anonymous bootstrap endpoint served by a chi router; Connect handlers generated by `pilotv1connect` registered via `http.StripPrefix`.
    - Depends on `internalauth.Manager`, `pilotv1connect`, chi routing, and frontend runtime config values.
  - **Highlights & Rules**:
    - `EnsureAnonymousSession` issues secure cookies (SameSite=Lax) and CSRF header, `ValidateCSRF` compares header/token via `subtle.ConstantTimeCompare`.
    - Frontend helper `readPilotSessionBootstrap` fetches `/auth/session` with same-origin credentials, validates payload schema, and demands a CSRF token.
    - Rule 1: Normalize `YONA_BASE_PATH` to a single leading slash without trailing slashes.
    - Rule 2: Always mount RPC handlers under `joinBasePath(basePath, "/rpc")` and strip that prefix before Connect sees requests.
  - **Facts for Drill-down**:
    - `rpc_mount_path`, `session_bootstrap_endpoint`, `session_cookies`, `csrf_validation`, `base_path_normalization`, and `frontend_session_bootstrap` entries capture the essential paths, behaviors, and conventions for session hardening.
