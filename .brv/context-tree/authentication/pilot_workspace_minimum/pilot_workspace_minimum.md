## Raw Concept
**Task:**
Describe the R0-2 pilot authentication and workspace minimum for yona-rust, covering proto surface, server services, persistence, and frontend shells.

**Changes:**
- Added pilot PilotService RPCs covering session reads, auth flows, workspace overview/default landing, project listing, and issue CRUD.
- Implemented server helpers for session bootstrap, CSRF validation, identifier normalization, and default landing persistence.
- Extended SeaORM persistence with app_users and default_landing_preferences plus repositories for authentication and defaults.
- Built connect-web based /login, /register, /me shells backed by buf-generated PilotService clients and workspace overview models.

**Files:**
- proto/yona/pilot/v1/pilot.proto

**Flow:**
Browser requests /api/auth/session to bootstrap CSRF/session info -> Connect router exposes PilotService RPCs for session/auth/workspace operations -> SignIn/Register RPCs validate identifiers, hash passwords, and issue authenticated sessions -> WorkspaceOverview/SetDefaultLandingPath manage default landing persistence -> Frontend shells at /login,/register,/me call these endpoints using connect-web clients with CSRF headers.

**Timestamp:** 2026-04-07

## Narrative
### Structure
Axum router builds BrowserRuntimeConfig and Connect router, routing connect calls to PilotServiceImpl which delegates to session helpers, repository backend, and asset handlers. Runtime config including rpcBaseUrl is injected into index.html so the frontend shells know where to issue requests.

### Dependencies
Connect/ConnectWeb for RPC exposure, bCrypt for password hashing, SeaORM repositories for persistence, buf-generated TypeScript bindings, and sanitize_default_landing_path helpers for safe landing paths.

### Highlights
Session bootstrap at /api/auth/session returns CSRF + cookies, registration enforces identifier normalization/unique login/email and hashed passwords, workspace shell shows default landing, favorites, and recent projects while reuse of connect-web keeps runtime consistent with backend RPC signatures.

## Facts
- **pilot_service_rpcs**: PilotService now exposes ReadCurrentSession, ReadAuthUiCapabilities, SignInWithPassword, RegisterWithPassword, SignOut, ReadWorkspaceOverview, SetDefaultLandingPath, ListProjects, ReadIssueDetail, and UpdateIssueState RPCs. [project]
- **persistence_entities**: SeaORM keeps projects, issues, app_users, and default_landing_preferences entities, enabling repositories for user lookup, issue reads/updates, and default landing persistence. [project]
- **frontend_shells**: Frontend auth/workspace shells for /login, /register, and /me use connect-web clients generated by buf and communicate with PilotService via CSRF-aware headers. [project]
- **default_landing**: Default landing path normalization plus persistence is enforced by sanitize_relative_path, normalize_default_landing_path, and the SetDefaultLandingPath RPC before values are stored or returned. [project]
