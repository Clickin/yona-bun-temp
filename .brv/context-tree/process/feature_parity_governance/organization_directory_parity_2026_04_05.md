## Narrative
### Structure
The /_app/orgs/ route loader validates search input (optional trimmed filter and pageNum ≥ 1), calls listOrganizations, and renders OrganizationDirectoryPage inside SiteShell. The page slices organizations into 30-per-page windows, maps each to ContentCards that show either logo images (when organizationLogoAssetId is populated) or initials generated by toInitials, and renders Prev/Next plus numbered pagination links that reuse buildOrganizationsHref to keep filters in the query string.

### Dependencies
Contracts in packages/contracts/src/org.ts ensure every organization payload is sanitized before services use db helpers from packages/db/src/org-project.ts; the domain layer organization-service wraps these helpers while enforcing authorization, and docs/provenance/core-parity-audit.md records the intended parity vocabulary and verification checklist for this Wave 0 capability.

### Highlights
As of Wave 0, the public organization directory shows logos derived from the newest organization attachments, preserves filter state during pagination, and enforces the legacy pageNum pagination window size of 5 plus Prev/Next anchors, aligning UX and backend validation rules noted in the parity audit.
