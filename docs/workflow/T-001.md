# T-001: Implement parallel orchestration workflow support

> Status: `historical`
> This task artifact belongs to a prior orchestration workflow and is preserved for historical reference only. It is not part of the current Yona canonical implementation baseline.

## Goal

- Operationalize the AGENTS.md parallel orchestration process in `agentctl` so teams can:
- generate phase-0 multi-agent planning packets,
- merge agent plans with deterministic priority,
- schedule dependency-safe parallel waves with path-conflict locking,
- and enforce explicit closure approval before marking tasks `DONE`.

## Scope

- Added `orchestrate` command group in `scripts/agentctl.py`:
- `orchestrate kickoff` builds a shared planning packet for `PLANNER/CODER/TESTER/DOCS/REVIEWER`.
- `orchestrate merge` merges 5 agent payloads using priority order:
  `REVIEWER > PLANNER > CODER > TESTER > DOCS`.
- Added path-aware parallel planning support:
- task schema supports optional `parallel_paths`.
- `task add` / `task update` now support `--parallel-path` (+ replace mode).
- `task waves` computes execution waves with lane cap (`--max-lanes`, default `3`) and conflict policy (`--missing-path-policy`).
- Added closure approval flow:
- `task approve` records `Approval:` comments.
- `finish --require-approval-comment` enforces approval-gated closure.
- Updated `docs/agentctl.md` quickstart and reminders for new commands.
- Added unit tests in `tests/test_agentctl_parallel.py` for:
- wave grouping, dependency ordering, conflict serialization,
- merge priority resolution,
- approval comment detection.
