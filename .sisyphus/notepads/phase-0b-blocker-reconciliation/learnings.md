- 2026-03-13: The final PostgreSQL blocker was not the generated `tsvector` itself; the handcrafted `search_document` migration failed first because new foreign keys targeted legacy tables whose `id` columns are not declared unique in the migrated PostgreSQL schema.
- 2026-03-13: For the bounded search projection, permission metadata columns are enough for later SQL filtering, so the smallest safe PostgreSQL fix was to keep the same metadata columns, generated `tsvector`, and `GIN` index while dropping the unenforceable new foreign-key constraints from the migration artifact.

- 2026-03-13: For the frozen T9 snippet helper, the smallest green implementation is exact-keyword range extraction plus overlap merge; broader tokenization or multi-term snippet semantics are not needed for the current legacy assertions.

The missing behavior was a domain-level read-before-write guard that preserves project authorization outcomes, surfaces missing PRs as `DomainNotFoundError`, and rejects only reopen-on-open with `DomainValidationError`.

- 2026-03-13: In the app search route, `queryOptions(...).queryFn` is not a safe direct call site for route code because React Query types treat it as optional and framework-owned; the bounded route should call `readSearchPage({ data: request })` directly when it needs the app helper outside `useQuery` or `ensureQueryData`.
- 2026-03-13: The live bounded search page works most reliably with a post-hydration client fetch plus a tiny internal `/api/search` adapter, because the direct serverFn path was the easiest place for the Bun-SQL-backed search stack to leak into the wrong render/runtime context.
- 2026-03-13: Deferring the default `@yona/db` load in `packages/domain/src/search-service.ts` and delaying the Bun-SQL loader in `packages/db/src/index.ts` reduces eager runtime coupling, but the current dev runtime can still surface `bun:SQL...` transport failures for live search reads, so the bounded app path needs a stable empty-page fallback instead of surfacing that runtime text to users.
- 2026-03-13: The real durable fix for the live search route is to run the app dev server with `bun --bun vite dev` and keep the search page on the normal server-rendered `serverFn` path; transport workarounds were less reliable than fixing the runtime boundary itself.
- 2026-03-13: SQLite runtime migration robustness matters for the live app path because two migration directories in `drizzle/sqlite/migrations/` are intentionally empty. The cleanest runtime fix is to skip empty dirs, normalize comment-only SQL blocks, and record applied runtime migrations so the local DB can recover from partial bootstrap attempts.
- 2026-03-13: `apps/app/src/routeTree.gen.ts` is a useful final sanity check for app transport boundaries; the current tree has no `/api/search`, and the working bounded search flow now lines up with the registered `createServerFn` helper path instead of relying on any hidden API route.
- 2026-03-14: The bounded PR rejection issue was best fixed at the contract boundary: `pullRequestStateUpdateInputSchema` now accepts only `open` and `closed`, while `pullRequestStateSchema` still allows `merged` for read-side data that may already exist.
- 2026-03-14: The existing three-dialect search infra was already enough to remove the `LIKE` fallback entirely: PostgreSQL can query the generated `search_vector`, MySQL can reuse the existing FULLTEXT index, and SQLite can query `search_document_fts` through `MATCH` and `bm25` without changing the hydration shape.
- 2026-03-14: Case-insensitive matching in the query layer exposed the last snippet mismatch; lowering only the search comparison while slicing the original text keeps snippets bounded and readable without inventing broader query parsing semantics.
